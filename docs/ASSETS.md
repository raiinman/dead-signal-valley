# Current asset provenance

The café uses 15 individually generated Meshy asset types, linked into an enterable assembly. Models, UVs and original 2048px PBR texture maps are retained in the GLBs. No whole-building generation is used.

The accepted parts and transforms are in `dist/building-test/assets.json`. Their runtime paths, including the reused original espresso, are relative to that manifest. `evidence/cafe-source-hashes.json` records hashes captured from the accepted source models before packaging. `docs/runtime-manifest.json` records every deployed file.

The original espresso source is also retained in `evidence/meshy-cafe-source.glb` for direct fidelity verification. This duplicate is a shared Git blob, not a second model download at runtime. The older initial conversion narrative in `MESHY-ASSET.md` is provenance only; the current runtime uses the faithful full-detail asset, not that reduced conversion.

Targeted component cleanup removed stray geometry from selected architectural/display parts. Clear display panes were added separately. The room uses the measured walk grid. Minor generated-source blemishes, approximate glass and stepped gable seams remain visible. Physical-phone performance is unverified.

Three.js r128 and its GLTFLoader are vendored with their license files. Other town models, signs and surface maps are generated by the runtime code. No external images, model service or paid API is required to run the project.
